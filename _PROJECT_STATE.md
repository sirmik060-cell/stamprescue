# StampRescue — состояние проекта на 2026-11-10 (вечер)

Это входной промт для новой сессии. Загружай его целиком ассистенту вместе с фразой

## Что это и цель
- Проект: `C:\Hermes_sandbox\StampRescue` — универсальный инструмент для создания ЛЮБЫХ
  печатей на базе старой программы «stamp 0.85» + восстановление печатей со сканов (LaMa-инпейнт).
- Переход на Rust/Godot НЕ нужен: LaMa (ONNX) и PDF (PyMuPDF) уже закрыты на Python/PySide6.
- В перспективе: vision-блок (определение типа печати, помощь с заменой/вставкой).
- Обсуждение предыдущей разработки: `_discussion_full.txt` (114 сообщений) в корне проекта.

## Пользователь и правила
- Отвечать по-русски.
- Перед ЛЮБЫМ изменением файла делать копию `.bak` (например `stamp_builder.py.bak5`).
- Пользователь проверяет результат визуально по скриншотам — после правок делать PNG-тесты
  и показывать их (MEDIA:), а правки UI подтверждать скриншотом GUI.

## Команды (проверены, использовать именно их)
- Python: `.venv/Scripts/python.exe` (venv на 3.13, создан uv; зависимости в requirements.txt).
- Рендер-тесты: `.venv/Scripts/python.exe tools/test_render.py` → 16 кейсов в `result/tests/`.
- GUI-смоук без экрана: `QT_QPA_PLATFORM=offscreen .venv/Scripts/python.exe tools/test_gui.py`.
- Тест очистителя скана: `.venv/Scripts/python.exe tools/test_clean.py` (12 проверок
  own/foreign + smart_fill → `result/tests/31_clean_*.png`).
- Сборка EXE:
  `.venv/Scripts/pyinstaller.exe --name StampRescue --onedir --windowed --noconfirm --add-data "models;models" --collect-all pymupdf --hidden-import fitz main.py`
  (НЕ `--collect-all fitz` — старый вариант ломает EXE, у новой PyMuPDF пакет `pymupdf`).
- Запуск EXE для проверки: `QT_QPA_PLATFORM=offscreen ./dist/StampRescue/StampRescue.exe` в
  background, потом `tasklist | grep -i StampRescue`, затем `process_manage kill`.

## Архитектура (коротко)
- `stamp_builder.py` — ядро: spec (JSON) → рендер PIL; `default_spec()`, `render_stamp()`;
  окно `BuilderWindow` там же (список слоёв + редактор параметров по SCHEMA).
- Типы слоёв: band, ring, arc_text, center_text, emblem, pic_frame. Глобальные поля spec:
  form(ellipse/rect/circle), w_mm, h_mm, rot_deg, noise_pct, corner_mm, dpi.
- `core/inpaint.py` — LaMa; `find_lama_model()` ищет lama.onnx рядом с EXE и в `_MEIPASS` (PyInstaller 6 кладёт данные в `_internal/`).
- `ui/main_window.py` — главное окно (скан, выделение рамки, ВОССТАНОВИТЬ, кисть/ластик, кнопка Конструктор).
- `presets/jenti_example.json` — реальный пресет пользователя для регрессии.

## Реализовано (закрыто предыдущими партиями правок)
1. Lama в EXE: поиск `_internal/models/lama.onnx` + внешний путь рядом с exe — работает.
2. Печать без рамок: толщина ring/band = 0 не рисуется; нумерация слоёв `ring #1`, `ring #2`.
3. Индивидуальные стили символов/фрагментов везде тегами: `{size=3.5;font=Times;bold;color=r,g,b;w=90;h=110}`
   (снимается `{!bold}`), работают в дугах и центре; парсер `parse_runs`, висячий тег в конце строки работает.
4. Дуги: `ashift_mm` (−60..60) — сдвиг по дуге; притяжение к rect идёт по периметру
   (по прямым сторонам ровно, поворот только в углах).
5. rect: выбор «Углы прямоугольника: прямые/скруглённые» + `corner_mm` (активен только для скруглённых).
6. Центр свободный: `align` (center/left/right), `dx_mm`/`dy_mm` на блок; теги строки
   `{align=left|center|right;dx=..;dy=..}` в любом месте строки.
7. Построчный редактор центра: каждая строка = поле текста + свой кегль + свой шрифт +
   жирность + цвет (`L["line_styles"]`, UI-методы `_build_lines/_line_set/_line_add/_line_del`).
8. Интервал строк центра: высота строки = метрики шрифта (впритык при 0), диапазон −8..10 мм
   (минус = наезд строк друг на друга).
9. Шрифт: Times/Times New Roman реально подхватывает `times.ttf/timesbd.ttf`; подбор имени
   нечувствителен к регистру, «Times NR» → Times New Roman. Нерезкость (noise_pct) размывает
   засечки — при претензии «нет засечек» проверять сначала noise_pct=0.
10. Подсказки-«простыни» про теги из формы убраны (пользователь просил).
11. Дуги ellipse/circle (v3.5): буквы раскладываются по ДЛИНЕ ДУГИ в пикселях (таблица длины
    дуги t∈[−2π..2π], поиск бисектом), а не «пиксели как радианы» (из-за этого был разнобой
    «оГодр»). Кривая — истинный эллипс/окружность (суперэллипс e=1.5 убран). Top-центр таблицы

25. v3.8.3 Пипетка ЧУЖОГО = приказ, приоритет над «своим» (баг пользователя:
    синяя полоса при пурпурной печати была ЗЕЛЁНОЙ в предпросмотре маски):
    - Причина (`core/clean.py`): «близость к чужому» мерилась проекцией на
      направление эталона — синее проецируется почти параллельно пурпуру (общий
      сильный B-канал) → полоса попадала в own; плюс `foreign &= ~own` всегда
      отдавала приоритет «своему».

## Критичные грабли
- SCHEMA-кортежи параметров: ровно 4 элемента (key,kind,a,b) — иначе ValueError в редакторе.
- Файлы проекта местами CRLF: при программной замене читать с `newline=""` и матчить \r\n
  (`tools/test_render.py` — наоборот, LF).
- Path-guard блокирует терминалу `C:\Windows\Fonts`, `Z:`, `Y:`, Desktop; для шрифтов —
  `execute_code`/PIL (obходят guard).
- `process_manage` в tool_call: action="stop" не проходит валидацию — использовать "kill".
- EXE-смоук: `&` в foreground terminal запрещён — запускать background=true без notify.
- Тесты и vision-проверки обязательны после каждой партии правок до отчёта пользователю.
- lama.onnx (наш fp32 export) отдаёт выход в 0..255, НЕ 0..1 — `_norm_out()` в
  `core/inpaint.py` обязателен; при смене модели сначала смотреть raw min/max выхода.
- Fixed-size ONNX: окно тайла строго fixed_hw; если сторона кропа меньше окна —
  `copyMakeBorder(BORDER_REPLICATE)` до размера окна (иначе InvalidArgument).
- EXE-сборка только через `StampRescue.spec` (`pyinstaller --noconfirm StampRescue.spec`);
  прямой вызов `stamp_main.py` неверен — вход это `main.py`.
- Панель с контентом выше экрана ОБЯЗАТЕЛЬНО в QScrollArea: QVBoxLayout без скролла
  при нехватке высоты сжимает виджеты ниже высоты шрифта (текст обрезан, «кнопок
  нет»), без исключений. Сайдбар v3.8+ = side(QFrame) → side_scroll(QScrollArea) →
  side_body(QWidget); снимки — через side_body.grab().
